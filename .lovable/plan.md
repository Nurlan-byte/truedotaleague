# Этап 1 — команды и профили

## Что сейчас в базе (проверено чтением)
- Таблица профилей: у гостей и вошедших игроков нет никаких прав. Политики есть, но без прав они не работают.
- Поля профиля:
  - Публичные: id, nickname, avatar_url, bio, mmr, role_position, profile_url, team_name, team_role, looking_for_team, competitive_rating, created_at, updated_at.
  - Приватные: discord_id, discord_username, discord_global_name. Email в профиле не хранится, он лежит только в аккаунте авторизации.
- Для собственных Discord-данных уже есть функции `get_my_discord_identity` и `save_profile_for_review`.

## 1. Права доступа (одна новая миграция, только права, без изменения данных)
- Гостям и вошедшим игрокам выдаётся чтение только публичных полей профиля. Discord-поля остаются закрытыми для всех, включая чужие профили.
- Права на запись в профиль не выдаются: сохранение идёт через существующую серверную функцию.
- Таблицы, команды, игроки, рейтинги и результаты не меняются, существующие миграции не трогаются.
- Отдельно, ничего не открывая: отзываются лишние права на запись в заявки и журнал (сейчас их блокирует RLS) и вызов `publish_draft_result` гостями. Это сужает доступ, а не расширяет его.

## 2. «Моя команда» (src/routes/my-team.tsx)
- Команда ищется по составу или по владельцу. Выбор старых дублей определён: новейшая команда, в которой игрок состоит.
- Показывается: название, тег, логотип, капитан, состав, рейтинг каждого игрока и суммарный MMR основной пятёрки и всего состава.
- Действия зависят от роли:
  - владелец: приглашения, исключение, логотип, удаление;
  - игрок: покинуть команду.
- Пока идёт загрузка, вместо формы показывается индикатор. При ошибке выводится понятный текст с кодом ошибки базы и кнопка «Повторить». Форма создания появляется только при успешной загрузке без команды.
- Создание идёт только через `create_team`. Кнопка блокируется до ответа сервера, затем данные перезагружаются и сразу показывается новая команда. Дубль невозможен: сервер вернёт «уже в команде».

## 3. Профили
- `use-auth.ts`, `players.tsx`, `players.$playerId.tsx`, `league-admin.ts` и `discord-notify` читают только публичные поля (они уже так делают). Ошибки чтения больше не проглатываются.
- `profile.tsx`:
  - Discord-данные берутся через `get_my_discord_identity`;
  - сохранение идёт через `save_profile_for_review`, а не прямой записью, которая сейчас падает.

  Перед изменением прочитаю и сверю поведение этой функции. Если она меняет логику (например, отправляет профиль на модерацию), остановлюсь и спрошу.
- Вход через Discord, ключи и callback не трогаются.

## 4. Тесты и проверки
- Автотесты (vitest) на логику выбора команды, суммы MMR и разбор ошибок.
- Проверки базы под ролями гостя и вошедшего игрока (в транзакции с откатом):
  - публичные поля читаются, Discord-поля дают отказ;
  - чужую команду нельзя изменить (`owner_required`);
  - повторный `create_team` возвращает `already_in_team`.
- Под аккаунтом владельца Team Spirt в превью (браузер): команда видна, состав виден, профили открываются; пользователь без команды видит форму.
- Проверка типов и сборки.
- Публикация только после вашего подтверждения.

## Риски
- Новые столбцы профиля по умолчанию будут закрыты, пока для них явно не выдадут права. Это плюс для приватности, но в будущем потребуется помнить об этом.
- `save_profile_for_review` может работать иначе, чем текущая форма (модерация). Будет проверено до замены.
- У Adilslayer404 четыре старые команды. Они не удаляются, показывается одна, выбранная по правилу выше.
- Competitive Rating, турнирные правила и Discord на этом этапе не меняются. Разделение Dota 2 MMR и TDL Competitive Rating переносится на этап 2.
