# Team Dashboard 2.0 — Этап 1: аудит и план

## Что есть сейчас (проверено)
**Страницы:** `src/routes/my-team.tsx` (вся «Моя команда» одним файлом), `src/routes/join.$token.tsx` (вход по ссылке), `ApplyDialog.tsx` (заявка), помощники `src/lib/my-team.ts` (+ тесты), `src/lib/divisions.ts` (лимиты дивизионов).

**Таблицы:** `teams` (название, тег, логотип, владелец), `team_members` (игрок + `position`), `team_captains`, `team_invites`, `team_invite_links`, `applications`, `tournament_participants`, `matches`, `placements`, `points_ledger`, `profiles` (`mmr` = Dota 2 MMR, `competitive_rating` = TDL CR из роли Discord).

**Серверные функции (все с проверкой прав):** `create_team`, `invite_player`, `cancel_invite`, `list_team_invites`, `accept_invite`/`decline_invite`, `get_team_invite_link`, `preview_team_invite_link`, `join_team_by_link`, `manage_team` (logo / remove / leave / delete), `submit_application`, `withdraw_application`, `reacknowledge_regulation`, `admin_delete_team`, `refreshTeamRatings` (обновление CR из Discord).

**Как считается рейтинг:** турнирный допуск и сумма команды сейчас идут по Competitive Rating; MMR Dota 2 хранится отдельно. В интерфейсе местами показывается «MMR», хотя число — CR. Это нужно развести.

## Найденные пробелы
1. **Основной состав / запас:** отдельного поля нет, но есть `position` (0–4 основа, 5–6 запас — так уже проверяет `submit_application`). Новая колонка не нужна.
2. **Нет серверных действий:** переименовать команду/тег, передать капитанство, поменять позиции (основа ↔ запас, замена). Лимит 5+2 на сервере сейчас проверяется только как «не больше 7».
3. **Лимиты лиг** не хранятся в турнире — берутся из названия турнира через `divisions.ts`. Полей командного/личного лимита у турнира нет.
4. **Оплата** не хранится — блок оплаты показывать не будем.
5. **Отзыв ссылки-приглашения** есть («Новая ссылка»); персональные приглашения уже можно отменить.
6. Капитан = владелец команды (`owner_id`); `team_captains` — старые данные.

## Предлагаемые изменения базы (только с вашего подтверждения)
Одна миграция, только добавление, ничего не удаляет и не меняет данные:
- `manage_team` получает новые действия: `rename` (название+тег, проверка уникальности тега), `set_position` (перевод основа/запас/замена с проверкой ≤5 основных и ≤2 запасных), `transfer_owner` (только члену состава). Существующие действия не меняются.
- Необязательно: колонки `max_team_mmr`, `max_player_mmr` у турниров (пусто = берём из дивизиона). Без них лимиты остаются в `divisions.ts`.
- Все новые действия пишут в журнал аудита.

## Интерфейс (этапы 2–4)
- Разбить `my-team.tsx` на компоненты в `src/components/team/`: шапка команды, карточки статистики, состав (основа/запас), приглашения, «Доступные лиги», вкладки «Состав / Турниры / История».
- Меню «три точки» и нижние панели на телефоне, широкий dashboard с боковыми блоками на ПК, скелетоны загрузки, ошибки с «Повторить», светлая/тёмная тема.
- В каждой строке игрока раздельно: **MMR** (Dota 2) и **CR** (TDL).
- «Доступные лиги»: Amateur 16 500 / 4 500 на игрока, Challenger 26 500, Freedom без лимита; статусы по ТЗ и пометка «MMR не равен допуску».
- «Турниры»: заявки и статусы, подтверждённый состав, ближайшие и сыгранные матчи, ссылка на сетку — только из базы.
- «История»: турниры, W/L, места, Win Rate, история матчей; пустое состояние, если данных нет.

## Порядок
1. Миграция `manage_team` (после «да»). 2. Новый интерфейс на текущих данных. 3. Управление составом, капитанство, переименование. 4. Турниры и история. 5. Тесты (лимиты 5+2, проверка лиг), проверка на телефоне и ПК под капитаном и игроком.

## Риски
- Старые составы могут иметь больше 5 игроков на позициях 0–4: при первом открытии покажем предупреждение, сами не переставляем.
- Передача капитанства меняет владельца — действие необратимо без нового капитана, будет подтверждение.
